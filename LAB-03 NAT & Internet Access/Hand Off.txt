# FINAL NAT CONFIGURATION

CHR-HQ-1 memiliki satu rule:

```text
chain=srcnat
action=masquerade
out-interface=ether3
```

Konsep:

```text
PC1
192.168.10.10
      │
      ▼
CHR-HQ-1
      │
      │ masquerade
      ▼
192.168.100.254
      │
      ▼
CHR-ISP-1
192.168.100.1
```

Penting:

`masquerade` melakukan source address translation.

Jangan menyebut hasil NAT sebagai "selalu public IP".

Pada LAB-03:

```text
192.168.10.10 → 192.168.100.254
```

Keduanya merupakan private address.

# ASSESSMENT-03 WEAKNESSES

Konsep yang masih perlu diperkuat:

## 1. Source vs Destination

Ingat:

```text
SOURCE
= siapa yang mengirim

DESTINATION
= siapa yang dituju
```

Contoh:

```text
Source      : 192.168.10.10
Destination : 192.168.100.1
```

Setelah masquerade:

```text
Source      : 192.168.100.254
Destination : 192.168.100.1
```

Destination tidak berubah karena `srcnat`.

---

## 2. Routing vs NAT

Gunakan aturan:

```text
Routing
→ menentukan ke mana packet pergi

NAT
→ melakukan address translation

Connection Tracking
→ melacak state dan hubungan traffic
```

Jangan mencampurkan ketiga fungsi tersebut.

---

## 3. NAT Tidak Selalu Menghasilkan Public IP

Jangan mengatakan:

```text
NAT = private → public
```

Lebih tepat:

```text
NAT = address translation
```

Hasil translation dapat berupa address private maupun public, tergantung desain jaringan.

---

## 4. NAT Counter

Jika:

```text
PACKETS = 0
```

tidak otomatis berarti NAT gagal.

Pertama tanyakan:

> Apakah traffic tersebut memang seharusnya match rule NAT?

Contoh:

```text
PC1 → 192.168.10.1
```

tidak keluar melalui `ether3`, sehingga rule:

```text
out-interface=ether3
```

tidak match.
